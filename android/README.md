# BahnConnections Android · V61.2.1 RC1

Native WebView host, separately built from the Sites application. Default origin: `https://bahnconnections-de.a-stad.chatgpt.site/`; override only with `-PbahnConnectionsOrigin=https://your-host.example`. Gradle rejects paths, credentials, ports and non-HTTPS origins. The WebMessage transport checks the exact allowed origin and main frame; older WebViews without WEB_MESSAGE_LISTENER do not receive an unsafe JavascriptInterface fallback.

Build with JDK 17, Android SDK 35 and `./gradlew testDebugUnitTest assembleDebug assembleDebugAndroidTest lintDebug`. `connectedDebugAndroidTest` runs the persisted-session/notification/explicit-stop test on an emulator. GitHub Android CI separates build/JVM tests from emulator APIs 26, 33 and 35. A successful web build is not an APK or device test. Debug artifacts are not a signed Play release. The specialUse service declaration requires Play policy review.

Follow starts only on an explicit web Follow action. Permission approval resumes the pending user action; denial does not start a service. The foreground service stores the complete session synchronously, restores it on a sticky process restart, and polls the same first-party trip API every 75 seconds without an Activity. Requests have an 8-second connect/read timeout, a 2 MB response cap, no redirects and no simultaneous network polls. Late responses cannot overwrite Stop or a newly selected train. Task removal does not stop the service; Stop in the notification or the web controls clears the stored session and notification. Settings → App reflects the persisted native session after a WebView reload.

Only an exact segment with fresh provider data can update the delay and time-based progress. Progress is labelled a prognosis model, never GPS, and disappears after 150 seconds, on cancellation, invalid times, or a route conflict. The ongoing notification remains visible with an honest stale/conflict status. No replacement route or timetable is fabricated when endpoints change. First-party API failure, authentication or rate limiting means no refresh; it does not silently authenticate stale data.

Android can still stop an app through Force Stop, Task Manager, revoked permission, reboot, or device power policy. No application can guarantee a notification against those system controls. The app respects an explicit Task Manager stop and does not automatically restart it on launch. Emulator results do not replace a physical Android 14/Realme battery-policy check, permission-denial/retry, actual low-memory process death, WebView reload, background/recents removal, offline/online, and cross-origin iframe security tests. These remain release blockers until recorded against the final build.
