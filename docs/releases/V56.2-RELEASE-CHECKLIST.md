## 3. Veröffentlichung vom Handy (nach Freigabe)

**Bevorzugt: Cloudflare Workers Builds via GitHub**, ohne separate Token-Übermittlung an ChatGPT:

1. Nach bestandenem Quality-/Cloudflare-Check und manuellen Freigaben PR #64 auf `main` mergen (oder zuerst einen geprüften Staging-Branch für eine Vorabversion einrichten).
2. Im Cloudflare-Dashboard **Workers & Pages → Create application → Import a repository** auswählen und GitHub einmalig freigeben.
3. `Cola968/BahnConnections` auswählen. Worker-Name **`bahnconnections-standalone`**, Root-Verzeichnis Repository-Wurzel, Produktionsbranch **`main`**.
4. Build: **`pnpm build:cloudflare`**; Deploy: **`pnpm deploy:cloudflare`**. Keine automatischen Standardbefehle übernehmen.
5. **Save and Deploy** nur nach bewusster Freigabe auslösen. Cloudflare liefert anschließend eine tatsächliche `workers.dev`-URL; bis dahin keine URL erfinden.
6. Auf der **neuen** URL `/version.json` prüfen (`version: "56.2"`) und Reiseplaner, Live-Abfahrten/Ankünfte, Störungsansicht, Zugradar, Mobile und PWA persönlich testen.
7. Erst nach erfolgreichem Smoke-Test und bestätigten Datenrechten die Adresse weitergeben.

**Alternative GitHub Actions:** Workflow `Standalone Cloudflare Workers` nach Merge manuell mit `publish=true` starten; dafür müssen `CLOUDFLARE_ACCOUNT_ID` und `CLOUDFLARE_API_TOKEN` **nur in GitHub Actions Secrets** gesetzt werden. Standardmäßig wird nichts publiziert. Beide Wege nicht parallel automatisch betreiben.

## 4. Rückfallplan

- Originale ChatGPT-Sites-URL bleibt von der separaten Cloudflare-Worker-Veröffentlichung unabhängig.
- Falls die neue Cloudflare-Version fehlschlägt, Veröffentlichung zurücknehmen beziehungsweise im Cloudflare-Dashboard auf die letzte funktionierende Deployment-Version zurückgehen; danach Ursache analysieren und PWA-Cache/Version prüfen.
- GitHub-Stand vorher markieren bzw. Merge-SHA notieren. Bei Bedarf Änderung auf `main` revertieren und erneut Qualität prüfen.
- Keine geheimen Zugangsdaten in Dokumenten, Issue-Kommentaren, Logs oder Chat veröffentlichen.

**Abgrenzung:** Hier wird eine **Web-/PWA-Version** vorbereitet. Ein Google-Play-Store-Release benötigt separat ein signiertes Android-Paket, Entwicklerkonto und Play-Console-Freigabe.
